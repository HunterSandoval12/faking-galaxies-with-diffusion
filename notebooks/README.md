# Google Colab tutorials

Tutorials for the project. Each notebook
runs top to bottom in Google Colab and keeps its data on Google Drive in `MyDrive/galaxy10_tutorial/`. Outside
Colab it uses local folders instead (`galaxy10_tutorial_drive/`, `galaxy10_tutorial_work/`; both git-ignored).

|---|---|---|---|
| 1 | [`01_Dataset_Tutorial.ipynb`](01_Dataset_Tutorial.ipynb) | CPU | every code cell run locally |
| 2 | [`02_Model_Description_Tutorial.ipynb`](02_Model_Description_Tutorial.ipynb) | GPU (T4) recommended | every code cell run locally |

**Running a tutorial:** open it in Colab (the *Open in Colab* links in the main README, or *File > Upload notebook*),
then *Runtime > Run all*. Run Tutorial 1 first: it creates the `training` / `validation` / `testing` directories that
the others read. Tutorials 2-6 download the trained models, the synthetic set and the training logs with `wget` from
the GitHub Release `weights-v1` and check their SHA-256 checksums; the Stable Diffusion v1.5 base weights come from
Hugging Face.

**FAST mode.** Tutorials 5 and 6 train models. By default (`FAST = True`) they use a fixed-seed 10% stratified subset
of the training images, a few classifier epochs, 200 LoRA steps and a handful of generated images, so they finish in
minutes on a free Colab T4; `FAST = False` runs the paper's full settings (hours on a T4). Their final results cells
load the released weights. On GPUs without bf16 hardware (the T4) they train in fp16 with a gradient scaler.

**Editing a tutorial:** each notebook is generated by a script in `_build/` (shared pieces in `_build/nbcommon.py` and `_build/nbtraining.py`),
so edit the script and rebuild, e.g. `python notebooks/_build/build_01_dataset_tutorial.py`. The execution-time
tables are filled from a local test run (`--times`). The notebooks are stored without outputs.
